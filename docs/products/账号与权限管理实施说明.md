# 账号与权限管理实施说明（内部账号 / BigQuery）

> 给新对话窗口用的开工文档。  
> **范围：** 系统内开账号 → 发给内部同事用；账号与权限落 **BigQuery**；登录仍用现有 Cookie 会话。  
> **明确不做：** Google 登录、Firestore 控制库、Step 5 AI、媒体 Signed URL 细权。  
> **DDL：** [`sql/ddl/007_app_user_access.sql`](../../sql/ddl/007_app_user_access.sql)（增量）；已同步进 [`sql/ddl/base_tables.sql`](../../sql/ddl/base_tables.sql)  
> 权威裁剪自：方案第 28 / 38 章 H04（身份改为内部账号，不做 OIDC）。

更新时间：2026-09-24

---

## 0. 一句话结论

**不要谷歌登录。** 在 BQ 建 `app_user` + `app_user_access`，管理员在工作台开账号、配品牌与动作；API 登录查表，读数据时按 `brand_keys` 过滤。

---

## 1. 要解决什么问题

| 现在 | 目标 |
|------|------|
| `.env` 只有一个账号 | 多名内部同事各自账号 |
| 登录后等于全站管理员 | 按品牌限制可见数据；按开关限制改映射/分类树/管账号 |
| 权限改不动要改代码 | 改 BQ / 管理页即可 |

**心智：** 没账号进不来；有账号但没配品牌 → 看不到业务数据；客户端自报品牌无效。

## 3. 实施计划（Plan）

### 阶段 A — 表与类型（0.5 天）

| # | 任务 | 产出 |
|---|------|------|
| A1 | 在 BQ 执行 `007_app_user_access.sql` | `review_control.app_user`、`app_user_access` |

**完成标准：** 能在 BQ 控制台看到两张空表（或已插入种子管理员）。

### 阶段 B — 登录改读 BQ（1 天）

| # | 任务 | 产出 |
|---|------|------|
| B1 | `auth`：按 username 查用户 + 校验 `password_hash`（bcrypt） | 不再只靠 env 双变量 |
| B2 | 登录成功加载有效 `app_user_access`（`valid_to IS NULL`） | 会话可带 policy 或请求内懒加载 |
| B3 | `GET /api/auth/me` 返回脱敏 policy | 前端藏菜单 |
| B4 | 无有效 access 或 `disabled` → 禁止登录或 403 | 默认拒绝 |
| B5 | 保留 env bootstrap：表空时可用 env 账号登录并提示去建种子用户 | 防把自己锁死 |

**完成标准：** 用 BQ 里两个测试号能登录；停用账号登不进。

### 阶段 C — 服务端按品牌过滤（1～2 天）

| # | 任务 | 产出 |
|---|------|------|
| C1 | `applyBrandScope(policy, filters)` | brand `*` → 不过滤；否则强制 IN 列表 |

| C3 | 写路径：`can_edit_mapping` / `can_edit_taxonomy` / `can_manage_users` | 无权限 403 |
| C4 | 未映射行：不得靠 `brand IS NULL` 越权 | 与方案第 28 章一致 |

**完成标准：** 仅 SKT 的账号在分析/评论里看不到其他品牌。

### 阶段 D — 管理页（1～2 天）

| D3 | 侧栏入口 | 仅管理员可见 |

## 4. 表设计（与 DDL 一致）

Dataset：`review_control`（控制/配置，不是评论事实表）。

### 4.1 `app_user`

| 列 | 类型 | 说明 |
|----|------|------|
| `user_id` | STRING | 主键语义 |
| `username` | STRING | 登录名，唯一 |
| `display_name` | STRING | 展示名 |
| `password_hash` | STRING | bcrypt 等，**禁止明文** |
| `status` | STRING | `active` / `disabled` |
| `is_bootstrap_admin` | BOOL | 可进管理页的标记（仍建议配合 `can_manage_users`） |
| `created_at` / `updated_at` | TIMESTAMP | |
| `created_by` / `updated_by` / `notes` | STRING | |

### 4.2 `app_user_access`（一人一行当前有效）

| 列 | 类型 | 说明 |
|----|------|------|
| `access_id` | STRING | 行 ID |
| `user_id` | STRING | 关联用户 |
| `brand_keys` | ARRAY\<STRING\> | `[]` = 无数据；含 `*` = 全部品牌 |
| `country_codes` | ARRAY\<STRING\> | `[]` = **不限制国家**（首期约定） |
| `can_view_review_text` | BOOL | 原声 |
| `can_view_media` | BOOL | 占位 |
| `can_export` | BOOL | 占位 |
| `can_edit_mapping` | BOOL | 产品映射 |
| `can_edit_taxonomy` | BOOL | 问题分类树 |
| `can_manage_users` | BOOL | 账号管理 |
| `policy_version` | INT64 | 变更 +1 |
| `valid_from` / `valid_to` | TIMESTAMP | 当前有效：`valid_to IS NULL` |

SQL 文件：`sql/ddl/007_app_user_access.sql`。

## 5. API / UI 清单

| 接口 / 页 | 说明 |
|-----------|------|
| `POST /api/auth/login` | 查 BQ 用户 + 哈希校验 |
| `GET /api/auth/me` | 用户 + policy |
| `GET/POST /api/admin/users` | 管账号 |
| `PUT /api/admin/users/:id/access` | 改品牌与开关 |
| `PUT /api/admin/users/:id/password` | 重置密码 |
| 前端 `/settings/users` 或「账号与权限」 | 仅 `can_manage_users` |
| reviews / analytics / mappings / taxonomy | 读过滤 + 写鉴权 |
