## 0. 先对齐一句话目标

差评分析**不必一上来就依赖 AI**。建议拆成两条轨：


| 轨道                 | 依赖 AI？     | 交付物                       |
| ------------------ | ---------- | ------------------------- |
| **A. 量化总览 + 原声下钻** | 否          | 能按品牌/产品/时间看评论与低星表现，并能点到原文 |
| **B. 问题分类与语义分析**   | 是（或强规则+人工） | 拆句、多标签问题树、证据片段、复核队列       |


**推荐顺序：先 A，再 B。** A 验收通过后，B 才有干净分母与可下钻证据。

### Step 1 — 聚合 API + 数据读路径（2～4 天）

**目标：** 后端能按筛选返回总览数字，数据只读 Serving/Core。

建议接口（命名可调整）：


| 接口                             | 作用                              |
| ------------------------------ | ------------------------------- |
| `GET /api/analytics/overview`  | 评论数、均星、1～3 差评率、4～5 星率、映射覆盖率     |
| `GET /api/analytics/trend`     | 按日/周：评论量、均星、低星率                 |
| `GET /api/analytics/breakdown` | 按品牌 / SPU / SKU / 国家 / 平台 Top N |
| （复用）`GET /api/reviews`         | 下钻列表；与总览同一套筛选参数                 |


实现要点：

- [x] 统一筛选：`dateFrom/dateTo`、`brand`、`spu`、`sku`、`country`、`platform`、`ratingMin/Max`、`mapped`（API 已支持；分析页 UI 暂无「是否映射」）
- [x] 只统计当前有效版本（`v_review_current` 或等价）
- [x] 空结果区分「无数据」vs「筛选过严」
- [x] 干跑可读内存评论；写真库读 BQ（与现有 `IMPORT_DRY_RUN` 一致）
- [x] `@voc/shared` 增加 Analytics 类型与文案

**完成标准：** 用已有导入数据，curl/接口能打出与评论列表大致对得上的总数与星级结构。 ✅

- [x] 全局筛选条（日期、品牌、SPU/SKU、国家、平台、星级；不做「是否映射」）
- [x] 指标卡：全部评论数、均星、1～3 星差评率、4～5 星率、映射覆盖率

- [x] 分布表：按品牌 / SPU / SKU / 国家 / 平台（服务端按评论数排序；表头点击改排序未做）
- [x] 点击某行 → 本页右侧侧栏原声（继承筛选）

导航：

- [x] 侧栏大类「分析」→「评论分析」
- [x] 路由 `/analytics`

**完成标准：** 业务同学能自己筛一个品牌+时间，看到数字，并点进 1～2 条原文核对。 ✅

### Step 5 — 轨道 B：分析流水线（真正开始依赖 AI）（1～2 周+）

**目标：** 对低星（或全量）评论跑拆句 + 多标签分类，结果可进看板。

> **状态：进行中。** 开工文档：[`AI语义分析实施说明.md`](./AI语义分析实施说明.md)。  
> **入口：** `/analytics`「差评分析」→ 当前筛选 ∩ 1～3 星 ∩ 有正文 ∩ 上限 N。

建议子步骤：

1. **存储契约**
  - [x] `analysis_run_id`、`input_hash`、绑定 `review_version_id`（+ `batch_id`）
  - [x] 片段级结果表（aspect / opinion / issue_ids / evidence offsets / confidence）
2. **Worker / Job**
  - [x] 异步跑批（勿堵在请求线程）+ stub 分类器
  - [ ] 可重跑、可按 publication/run 对比（MVP 每次新 batch）
  - [x] 失败 / 安全进 `pending_review`；无证据不上正式 issue
3. **模型与门槛**
  - [x] PackyCode/OpenAI 兼容适配器 + JSON schema（`llmClassify.ts`；配齐 `LLM_*` 即走 AI）
  - [x] 置信度只做路由（`LLM_MIN_CONFIDENCE`）；无证据 / 非法 id 不上正式 issue
  - [x] 安全线索进 pending_review（stub + LLM）
4. **看板增量**
  - [x] 本批 Top 问题面板（全站覆盖率 / Pareto 待补）
  - [ ] 指标：已分析覆盖率、含负面问题的评论率
  - [ ] Top 问题 Pareto、问题分析器（方案第 17.5 / 18 章）
  - [ ] 所有 AI 结论必须能点回原文证据

**完成标准：** 同一批评论：无证据的结果不上总览；有证据的问题数可下钻到句子。
